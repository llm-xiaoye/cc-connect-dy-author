# 面试题库规则

面试题库位于 `知识库/面试题库/<一级>/<子方向>/<题目>.md`，由本技能的题目提交流程维护。

## 什么时候写题目文档

- 作品的原始材料（作品标题/文案、图文说明、完整转写或 OCR）里出现“面试”两个字，就是面试类作品。脚本已判定并在 ready 结果里给出 `interview_required`；不要自行改判。
- 面试类作品两层都写：先按知识笔记规范写 `knowledge.md` + `analysis.json`（放在原主题目录），再写 `interview.json` 和题目正文。非面试类作品禁止写 `interview.json`。
- 一条作品可以对应多道题；至少一道。题目内容必须来自完整材料，模型补充要标明补充/核实并附链接。

## 选择目录

- 恰好两级：`["面试题库", "<一级>", "<子方向>"]`，每段不超过 24 字，不含路径符号，不用来源/媒体词。
- 先看 `question_catalog_file` 的 `categories`，能复用就复用。
- 推荐的一级起点：大模型基础、Prompt与推理、RAG、Agent、训练与微调、推理与部署、评测与安全、系统设计与工程、项目与表达。都不合适时可以新建一级；子方向按题目实际考点新建（如“意图识别”“检索与重排”“记忆管理”）。

## 新建还是合并

- `question_catalog_file` 只提供完整目录树和题目数量。先从完整材料提取核心问题、技术术语及同义词，写到 `item_dir/catalog-terms.txt`，执行 `catalog-search --run RUN_DIR --id ID`；读返回的 `questions.candidates`（标题、常见问法 `forms`、insight、sha256）。脚本检索全库，响应仅给候选；`has_more=true`、无命中或问题尚未覆盖时，细化词、换同义词或提高 limit，不能把词命中当语义等价或把无命中当全库缺席。
- **合并**：核心问题相同、一份答案能同时回答。先用 Read 读取目标文档全文，把读取时的 sha256（catalog 中的 `sha256`，或自己对文件求 SHA-256）填进 `expected_sha256`；正文写合并后的完整版本（吸收新材料的新论点、数据、追问），保留原标题。
- **各自成文**：主题相近但问法或考点不同。新题正文的“模型补充”里可以点明与哪道题的区别。
- 脚本会：拒绝读取后被改过的目标；拒绝同一作品重复并入；备份合并前的原文到 `.cache/dy-author/revisions/`；保留原文“我的补充”；更新 `source_aweme_ids`、`source_urls` 与“相关笔记”。

## 题目正文（body_file）

不写 YAML、一级标题、“相关笔记”“我的补充”（脚本维护）。六个二级小节按顺序全部出现且非空：

```markdown
## 题目与常见问法
面试官的原始问法，以及 2–4 种常见变体。

## 答题要点
- 1–2 分钟能说完的口述骨架，按说的顺序 3–6 条
- 每条一句话，是“说什么”，不是“为什么”

## 答题重点
面试官真正考察什么；必须说到的关键词/指标/取舍；最容易答错或丢分的地方。

## 参考回答
口述版完整回答（第一人称，可直接练习）。没有真实项目时写成方案设计，不编造“我们上线后提升 X%”。

## 追问与应对
常见追问 + 简要应对思路。

## 模型补充
对问题和答案本身的补充：材料的纠错、遗漏的考点、适用边界、需要官方核实的点（附链接）、与本库其他题的区别。
```

## interview.json

写在本条 `item_dir`：

```json
{"questions": [
  {"action": "new", "category": ["面试题库", "Agent", "意图识别"], "title": "意图识别怎么做",
   "tags": ["意图识别", "路由"], "insight": "规则、小模型、大模型三层漏斗，按成本分流", "body_file": "question-1.md"},
  {"action": "merge", "target": "知识库/面试题库/RAG/检索与重排/为什么需要重排.md",
   "expected_sha256": "<读取时的 sha256>", "title": "为什么需要重排", "tags": ["RAG", "重排"],
   "insight": "召回求全、重排求准", "body_file": "question-2.md"}
]}
```

`title` 是问题本身（可读、非纯数字），`insight` 最多 60 字。题目文档与知识笔记在同一事务提交；总索引出现“面试题库 / 一级 / 子方向”分组，总日志记为“新增面试题”或“合并面试题”（来源 DY）。

## 补录模式（`/dy-author 补录`）

补录处理已在库里、尚未进题库的面试类知识笔记。ready 结果给出 `note_file`（已有知识笔记）和 `material_file`（可核对的原始转写/OCR；没有时是笔记全文，`basis` 会注明）。只写 `interview.json` 与题目正文，不改原笔记正文；脚本会顺带补齐已核实的作者属性并刷新作者文档。
